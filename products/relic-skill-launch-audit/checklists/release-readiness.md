# Release Readiness Checklist

> 输出 `PASS`、`REVISE` 或 `BLOCKED`，每项都要附证据路径。

## 1. Trigger & scope

- [ ] frontmatter 有 `name`、`description`、版本和许可证
- [ ] description 包含明确触发意图和不适用场景
- [ ] 主流程能从输入走到输出，不依赖隐藏上下文
- [ ] 越界请求有拒绝或升级路径

## 2. Data & permissions

- [ ] 列出读取的文件、网络地址、环境变量和写入位置
- [ ] 声明敏感数据处理和最小权限
- [ ] 不包含密钥、本机路径、客户资料或未经授权的样本
- [ ] 有撤回、删除和保留期限说明

## 3. Compatibility

- [ ] 所有引用文件存在
- [ ] 路径使用相对路径或明确平台差异
- [ ] 安装说明至少在一个干净目录可执行
- [ ] 目标 Agent/IDE 和版本边界写清楚

## 4. Quality

- [ ] 有静态检查或测试
- [ ] 有至少一个脱敏示例
- [ ] 有资料不足、权限不足和来源冲突的失败分支
- [ ] 版本号、变更记录和发布包内容一致

## 5. Package hygiene

- [ ] 压缩包只包含目标版本和目标 edition
- [ ] 无 `.env`、缓存、内部工具目录、临时日志或 `node_modules`
- [ ] 无私钥、token、内网地址和本机绝对路径
- [ ] 解压后入口文件可直接定位

## 6. Buyer handoff

- [ ] 商品页写清输入、输出、限制和支持范围
- [ ] 开源版和商业版差异可核对
- [ ] 授权、更新、退款和转授权边界不互相矛盾
- [ ] 有下载校验值或可重复构建说明
