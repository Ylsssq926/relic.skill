# relic.skill 产品机会矩阵

> 版本：2026-10 · 用于决定哪些 Skill 值得先做成可交付商品。市场观察来自公开 Skill 排行、数字商品页面与本项目已有能力，不等同于销量承诺。

## 结论摘要

当前公开 Skill 生态的高频方向集中在软件工程、前端设计、媒体生成、社媒自动化和企业协作。通用代码审查、TDD、前端设计、浏览器自动化已经有强势免费供给；本项目更适合做“证据、治理、交接、交付”这一层，把原始资料变成可审计的组织资产。

## 产品候选

| 产品 | 目标买家 | 付费痛点 | 输入 | 可交付输出 | 首发优先级 |
|---|---|---|---|---|---|
| `relic-expert-handoff` | 企业 HR、技术负责人、顾问、交付团队 | 核心员工离开后，判断逻辑无法复制；普通交接文档没人问、没人信 | 文档、IM、会议纪要、访谈、事实补充 | 判断规则、证据索引、冲突表、交接包、问答入口 | P0 |
| `relic-skill-launch-audit` | 独立 Skill 作者、Agent 工作室、咨询师 | Skill 能跑但不敢发布：触发不稳、权限不清、包不卫生、销售页不完整 | Skill 目录、README、测试、打包脚本、许可证 | 审计报告、修复清单、发布包检查、销售页骨架 | P1 |
| `relic-team-memory` | 远程团队、飞书/Slack 用户、项目负责人 | 决策散落在聊天和会议里，新人重复提问，复盘无法复用 | IM 导出、会议纪要、邮件、项目文档 | 决策日志、责任人、未决问题、周报、onboarding 包 | P2 |

## 为什么不是通用 Prompt Pack

- 单纯 Prompt 很容易被免费内容替代，难以证明持续价值。
- 可售 Skill 应包含触发规则、输入检查、证据标注、失败分支、模板和验收命令。
- 买家付费的是减少交付风险和判断成本，而不是更多聊天话术。

## 首发商品组合

### Starter

- 一个独立 Skill 目录；
- 英文主文档 + 中文辅助说明；
- 脱敏示例数据；
- 本地运行与验收清单；
- MIT 授权，个人与商业用途均可使用。

### Commercial

- 商业场景配方与交付治理内容；
- 客户交付模板；
- 组织级治理和撤回说明；
- 优先支持与版本更新；
- 框架代码本身为 MIT，可自由再分发；付费部分仅限随包提供的内容与支持。

## 共享验收标准

1. `SKILL.md` 能独立说明触发条件、流程、输入输出和边界；
2. 示例不含真实个人资料、秘密、公司机密或虚构成真实证明的声明；
3. 所有核心结论可回溯到来源或明确标为待验证；
4. 有失败分支：资料不足、权限不足、来源冲突、撤回请求；
5. 至少有一个可重复的静态检查或测试；
6. 图片素材暂时用 `TODO(image): ...` 明确占位，不提交未经授权的图片。
